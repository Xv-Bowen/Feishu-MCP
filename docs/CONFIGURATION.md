# 配置与飞书权限

## 环境变量

| 名称 | 必需 | 存放与含义 |
|---|---|---|
| `SITE_ORIGIN` | 是 | 自己的新站点 HTTPS 源地址，必须与浏览器、OAuth issuer/回调一致 |
| `FEISHU_APP_ID` | 是 | 自己创建的飞书应用 App ID；不要复制其他人的值 |
| `FEISHU_APP_SECRET` | 是 | 服务端 secret，只放 Sites 密钥设置 |
| `TOKEN_ENCRYPTION_KEY` | 是 | 32 字节随机密钥的 64 位十六进制表示；只存服务端 |
| `DB` | 是 | Sites 提供的 D1 binding，不是需要贴入 `.env` 的数据库密码 |
| `CLIENT_MCP_PUBLIC` | 外部同站 OAuth 时 | `true`，配合可访问的站点入口，仍要求 OAuth 身份 |
| `SITE_SERVICE_ACCESS` | 否 | 旧私有桥接模式的平台服务访问凭据；普通同站部署不要设置 |
| `CLIENT_OAUTH_ORIGIN` | 否 | 旧独立 OAuth 网关模式使用；新部署默认同站 |
| `MCP_OAUTH_CLIENT_ID` | 否 | 兼容旧手工配置客户端；自动注册路径不需要 |

生成加密密钥可在自己的终端运行 `openssl rand -hex 32`，直接存入 secret 管理。不要把结果发到公开聊天、Issue 或 Git。**该密钥需稳定保存并安全备份**；直接更换会使已有密文无法解密，需要规划迁移或重新连接。开发变量与生产变量分开。

## 飞书应用配置

1. 在[飞书开放平台](https://open.feishu.cn/)创建自己的应用，记录 App ID 和 App Secret。
2. 将 OAuth 重定向 URL 精确设置为 `https://你的站点/auth/feishu/callback`，不要使用旧站域名；回调路径和协议必须匹配。
3. 在权限管理开通本功能所需的**用户身份权限**，发布应用版本并确认可用人员/租户范围。只开通机器人/应用身份权限不等于用户 token 有权限。
4. 在连接网站登录自己的 ChatGPT 账号，再授权飞书。按需选择扩展功能，权限变化后重新完成相应授权。
5. 运行连接检查。未授权的工具应明确报缺失 scope，而不是切换到其他人的 token。

完整 scope 由 `lib/core.ts` 的基础 scopes 与 `lib/features.ts` 的功能映射决定；[SCOPES.md](SCOPES.md) 从这两处生成。工具数量不等于 scope 数量；飞书可能合并/新增界面权限名称。

`drive:drive.metadata:readonly` 是用户身份的文件元数据权限，删除前的元数据核验需要它；不能以为 `drive:drive:readonly` 自动涵盖所有端点。写入还需要对应编辑权限，整文件删除需要 `space:document:delete`。具体可用性应核对飞书当前官方文档与原始缺失权限列表。

## 三层授权

| 层 | 决定什么 | 常见解决方式 |
|---|---|---|
| 应用权限/发布范围 | 应用能否申请 API scope、哪些人可使用 | 开放平台开通并发布；管理员批准 |
| 用户授权与资源权限 | 本用户 token 的 scope、文档/群/表访问 | 重新授权缺失功能；资源所有者分享；加入相应群 |
| MCP 客户端许可 | 客户端是否获准读/写 | OAuth `feishu.read` / `feishu.write`；旧只读连接需要增补写入授权 |

授权状态和“当前用户明确要求某个写入/删除”仍是两个条件。不要为了通过客户端安全提示而放宽服务端鉴权。旧固定 API key 兼容入口仅提供只读能力。

## 机器人

机器人状态、成员关系和公告读取适配代码已经包含。应用身份与用户身份权限分别检查；机器人需可用且在目标群中，租户与群类型限制仍适用。该实现不把机器人身份作为任意用户的越权后门，也不提供未获授权的机器人写入回退。
